# CowBot 0.1.10 — Self-hosted team mode, a default model, and a trilingual interface

CowBot 0.1.10 is the largest release since the local MVP. The same codebase now
runs as the local desktop app or as a self-hosted server for a small team, model
configuration separates the default model from the connections that supply it,
and the desktop interface ships in English, Simplified Chinese, and Traditional
Chinese.

## Highlights

- **Self-hosted team mode.** `cowbot-server` serves accounts, bearer sessions,
  workspaces, roles and invitations, channels, messages, tasks, approvals,
  audit, API tokens, and a workspace-scoped live event stream over HTTP and
  WebSocket. `RemoteClient` implements the same `Client` trait as the local
  runtime, and the server hosts the workspace data surfaces: memory, notes,
  conversations and their context, read-only previews, recorded prompts,
  workspace-scoped templates, and `.cowpkg` import/export. Passwords use
  Argon2id, sessions are stored as hashes, sign-in is rate-limited per source,
  and role checks resolve before every read or write. A multi-stage Dockerfile
  and a Compose file with Caddy are in `deploy/`, with the operations guide in
  `docs/SERVER.md`. See [ADR-0043](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0043-self-hosted-server-auth.md),
  [ADR-0044](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0044-workspace-membership-and-roles.md),
  [ADR-0045](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0045-collaboration-api-and-remote-client.md),
  [ADR-0046](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0046-deploying-the-server.md),
  and [ADR-0047](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0047-hosting-the-workspace-data-surfaces.md).
- **A default model and the connections that supply one.**
  Settings → Models now has one default-model switch above the list of
  connections. A connection records its protocol, endpoint, API key, model list,
  and per-model context windows; adding or editing a connection never changes
  which model runs. **Fetch models** seeds the context windows the endpoint
  reports and leaves unknown values blank instead of guessing. See
  [ADR-0048](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0048-default-model-and-connections.md).
- **A conversation follows the default or pins its own model.** User-created
  conversations record a model scope. The composer shows `· default` or
  `· pinned`, can switch to any model on the conversation's provider, and can
  return to following the default. Deleting a connection rewrites the
  conversations that referenced it, so no stale model name reaches another
  endpoint. Context meters, compaction, and router budgets count with the
  conversation model's tokenizer. See
  [ADR-0049](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0049-conversation-model-scope.md).
- **Trilingual interface and an account menu.** Every desktop surface is
  translated into English, Simplified Chinese, and Traditional Chinese through
  typed catalogues: a missing or extra key fails the frontend build instead of
  falling back silently. Language opens a Claude-style picker grid, follows the
  operating system language on first launch, and stores the device-local
  preference in `config.json`. The bottom-left row now shows
  `User · Workspace` and opens Settings, Language, Model configuration,
  Workspace settings, View changelog, and Learn more. Dates and times follow the
  selected language. See
  [ADR-0050](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0050-desktop-interface-localisation.md).
- **Desktop polish.** The window uses an in-app title bar instead of native
  decoration; composer controls sit below the input; the timeline follows a
  growing thread until you scroll away; a running reply swaps Send for Stop;
  slash-command drafting and argument completion were corrected; Settings →
  Memory can preview the next recall; and model discovery keeps the context
  window an endpoint advertises.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.9.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases migrate automatically through migrations `0018`–`0020`
when the app opens them: group routing policy, workspace-scoped templates, and
the conversation model scope. Back up the database before opening it with a new
build if you may need to return to 0.1.9.

`.cowpkg` packages from 0.1.9 and earlier still import. Prompt snapshots, LLM
usage, group turn rows, and model provider configuration remain device-local and
are never written to a package.

## Known limitations

- The desktop's settings do not yet offer choosing a server. A client that
  speaks the HTTP API or uses `RemoteClient` can reach one, and the local
  runtime remains the default way to use CowBot.
- Agent turns still execute in the desktop process with its model provider. The
  server stores and serves workspace state; a member without that provider
  configured cannot make an agent answer.
- `RemoteClient` reports server mode plainly for worktrees, in-process crew
  execution, live-turn cancellation, and process-local session decisions.
  Streaming a live turn over a remote transport is not built.
- The server is a small-team deployment for a network you control, not a public
  service. Multi-user concurrency defence for two people editing the same agent
  or rule is not implemented.
- Interface localisation covers the desktop chrome. Service diagnostics, agent
  profiles, template content, stored audit reasons, and the CLI remain in
  English; right-to-left layouts are not implemented.
- Worktree branches still cannot be merged back or turned into a pull request
  from the app. Prompt snapshots remain per-call evidence: audit events and tool
  calls are not yet linked to the snapshot that produced them.
