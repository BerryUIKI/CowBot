# CowBot 0.1.8 — Group conversations and agent memory

CowBot 0.1.8 turns conversations into multi-agent rooms and gives agents
durable, inspectable memory. A conversation can hold up to eight ordered
participants, each with an independent context branch, and a message is answered
by the participants it mentions, by an opt-in model router, or by the stored
default responder. Workspace and conversation notes plus four-scope memory
entries survive compaction and new conversations and are recalled within a
strict token budget. The context popover now explains the window with a colored
stacked bar.

## Highlights

- **Group conversations.** Create a conversation with two to eight ordered
  agents. Explicit `@mentions` resolve against the conversation's participants
  only, and `@team`, `@all`, `@everyone`, and `@here` expand to every
  participant in order. An opt-in router selects one to three participants when
  nobody is mentioned; with routing off, a stored default responder answers, and
  an unaddressed turn with no responder stays silent with a route notice. A
  mention of an agent outside the conversation is rejected with a notice instead
  of silently adding the agent. Membership is fixed for the life of the
  conversation. See
  [ADR-0032](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0032-group-conversations-and-routing.md)
  and the [M3 plan](https://github.com/BerryUIKI/CowBot/blob/main/docs/plans/M3-group-conversations-and-routing.md).
- **Independent context per participant.** Each participant keeps its own
  append-only context branch over the shared timeline. Replies are posted as
  each independent turn settles, so a fast agent does not wait for the slowest;
  the transcript shows the honest settle order and an **Answered by** line
  records the selection, router source, and any skipped or failed participants.
  Settled replies enter the other participants' branches as attributed peer
  entries for later turns. The header exposes one context tab per participant
  with its own meter, compaction, and clear actions. Group settings, ordering,
  peer attribution, and context branches round-trip in `.cowpkg` packages; turn
  routing records and LLM usage stay device-local.
- **Agent memory and shared notes.** A workspace note and one note per
  user-created conversation are edited as Markdown and injected before memory
  entries. Memory entries have four scopes — workspace-shared, agent,
  conversation-shared, and agent-in-conversation — with pins, review states,
  sources, and budgets. Recall is deterministic and bounded: pinned entries
  first, then FTS5 relevance with a LIKE fallback, within the workspace's note
  and recall token budgets. Notes and entries are reference data, never
  instructions. Agents can write memory through the approval-gated `remember`
  tool, and opt-in extraction stores up to three pending candidates per settled
  turn for review before anything is injected. Task executions recall the
  assignee's workspace, agent, and task-channel memory. Credential-shaped text
  is redacted on write and on package export. See
  [ADR-0033](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0033-agent-memory-and-shared-notes.md)
  and the [M4 plan](https://github.com/BerryUIKI/CowBot/blob/main/docs/plans/M4-agent-memory-and-shared-notes.md).
- **Memory surfaces in the desktop.** Settings → Memory edits the workspace
  note, recall and extraction flags, and token budgets, and lists entries by
  status and scope with add, edit, pin, approve, dismiss, archive, and delete
  actions. The conversation context popover edits the conversation note and
  shows the next turn's memory estimate; user messages offer **Remember this
  message**. The colored context indicator replaces the plain breakdown with a
  stacked bar and legend for messages, memory, system prompt, tools, the
  auto-compact buffer, and free space, plus token counts, percentages, the
  remaining tokens until auto-compaction, and **Compact now**. Unlabeled color
  is never the only signal, and unknown windows fall back to absolute tokens.
- **Group conversation UI.** The New conversation form creates a single or
  ordered group conversation with a fixed provider/model, a default responder,
  and a routing toggle. Participant chips mark the default responder, the
  composer offers participant-scoped mention autocomplete, and each tab can
  compact or clear its branch. A full branch is skipped without blocking the
  other participants.

## Smaller improvements

- `cowbot memory list`, `cowbot memory add`, and `cowbot memory archive` expose
  memory for verification and scripting.
- `cowbot message post --wait` reports group routing outcomes and the agents
  that answered, failed, or were skipped.
- `.cowpkg` packages carry conversation participants, conversation settings,
  context entries and events, notes, memory entries, and memory settings;
  imported memories stay reviewable, and credential-shaped text is redacted.
- Group conversations explain fixed membership in the context popover rather
  than offering controls that would not take effect.
- The context indicator uses the same categories and colors for single
  conversations, group participant tabs, and unknown windows.

## Why it matters

0.1.7 made work inspectable and bounded. 0.1.8 makes collaboration and memory
first-class: several agents can answer one request without losing their
individual context, a user can see and edit what an agent remembers, and every
injected token has a visible budget and a predictable recall order. Memory and
notes survive compaction and clearing, so the workspace gets more useful over
time without hiding state in an opaque store.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.7.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases migrate automatically through migrations `0013`–`0014`
when the app opens them: group participants and routing records, then notes,
memory entries, and the FTS5 recall index. Back up the database before opening
it with a new build if you may need to return to 0.1.7.

`.cowpkg` packages from 0.1.7 and earlier still import. New packages include
group conversation participants and context branches, notes, memory entries,
and memory settings; turn routing records and LLM call usage remain
device-local, and the device-local project registry and task worktrees are
never written to a package.

## Known limitations

- Group membership is fixed after creation; changing the team means creating a
  new conversation, and the old history stays intact.
- Automatic routing applies to user-created group conversations, not group
  channels or direct conversations. One fixed model serves the whole
  conversation, and participants cannot use different providers.
- Group turns cannot be cancelled, retried per participant, or grouped in the
  background panel; consolidated group-plan approval is deferred.
- Memory uses deterministic FTS5 and LIKE recall, not embeddings or vector
  search. Memory-aware routing, expiry automation, and cross-workspace sync are
  not implemented, and channel turns do not inject memory.
- Automatic memory extraction is opt-in and writes pending candidates for
  review; nothing extracted is injected until it is approved.
- Prompt-cache optimisation for Anthropic and Responses (M5), project-scoped
  knowledge and M6 structure, and Phase 2 self-hosted mode remain future work.
- Worktree branches still cannot be merged back or turned into a pull request
  from the app; inspect the diff and use normal git tooling.
