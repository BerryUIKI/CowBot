# CowBot 0.1.7 — Approval parity, visible context, and task worktrees

CowBot 0.1.7 is the largest desktop update since 0.1.6. It makes model context
visible and compactable, completes the five-mode approval model with workspace
rules, session decisions, Plan mode, and Bypass semantics, and adds
project-bound git worktrees with background task cards so work can run away
from the main checkout.

## Highlights

- **Conversations with an independent context.** Create a single-agent
  conversation from the sidebar. Each conversation has its own append-only
  context branch, fixed provider and model, and a header context ring with a
  popover showing percent used/left, per-category tokens, cache hit rate, and
  compaction controls. Manual compaction is always available; automatic
  compaction is off by default and can run at a configured threshold (80% by
  default). A full context blocks the composer and offers compact, clear
  context, or a new conversation. Clearing context never deletes the visible
  message history. See
  [ADR-0030](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0030-conversation-sessions-and-context.md)
  and the [M2 plan](https://github.com/BerryUIKI/CowBot/blob/main/docs/plans/M2-conversations-and-context.md).
- **Token usage accounting.** Every LLM completion records normalized usage:
  uncached, cached, and cache-write input tokens, output tokens, and reasoning
  tokens, with DeepSeek cache hit/miss fields and the provider's raw usage
  object preserved. Per-call rows back the conversation totals and cache hit
  rate shown in the context popover, and the desktop can store an optional
  context window and max output size per model. See
  [ADR-0029](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0029-token-usage-accounting.md)
  and the [M1 plan](https://github.com/BerryUIKI/CowBot/blob/main/docs/plans/M1-usage-accounting.md).
- **Approval rules and remembered decisions.** Settings → Approvals manages
  workspace allow / ask / deny rules per tool and, for `execute_code`, per
  command glob. Deny wins over Ask, Ask over Allow; rules are evaluated before
  the model evaluator and cannot soften a hard policy denial. Approval cards
  offer **Approve once**, **Approve for session**, and **Reject**; a session
  approval is remembered by tool (or exact normalized command) for the rest of
  the app run and can be reset from Settings. Imported rules travel with the
  workspace but start disabled until reviewed. See
  [ADR-0003](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0003-risk-classification-and-approval.md).
- **Plan mode that continues.** Plan mode denies every mutating tool, asks the
  agent for a numbered plan, and stores that plan with the task. Task detail
  offers **Approve plan and continue**, which marks the plan approved and
  re-runs the same task in Manual mode with the approved plan injected into the
  prompt. Plan mode also applies to channel and conversation turns.
- **Bypass with a safety setting.** Bypass permissions runs non-Critical calls.
  A new Settings → Approvals setting decides what happens to Critical calls
  under Bypass: **Allow** (default), **Ask** with a red approval card, or
  **Block**. Every other mode keeps blocking Critical calls. Selecting Bypass
  warns every time and keeps a red marker while active. Destructive
  `delete_channel` calls always ask a human, even under Bypass.
- **Worktrees and background tasks.** Settings → Projects registers local git
  repositories. A new task can opt into a per-task worktree on `cowbot/<slug>`
  under `<repo>/.cowbot/worktrees`; the run's file, command, and workspace tools
  are rooted there. Task detail shows the branch, diff, open-folder, and
  discard actions. Crew tasks share the submitted task through `Task.run_group`,
  and assignment/worktree events feed compact sidebar cards plus a Background
  panel with live status, progress, and the last finished runs. The Main
  Assistant can queue tasks into a registered project's worktree. Worktree
  records and repository paths stay on this machine and are excluded from
  `.cowpkg`. See
  [ADR-0031](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0031-task-worktrees-and-background-cards.md).
- **Source-filtered audit.** Every tool decision records its source — `rule`,
  `model`, `session`, `human`, `policy`, or `system` — and the matching rule
  when one decided the call. Settings → Audit lists decisions and filters by
  source.

## Smaller improvements

- A **Chat** entry in the footer navigation and Settings sections in the app
  sidebar.
- Task titles come from the runtime and render at body size; tasks can be
  archived, filtered, and managed from a context menu.
- The local user profile is editable, providers hold a full model list, and the
  composer has a model selector beside the approval control.
- The five approval modes are available in the composer and the task form:
  Auto, Manual, Accept edits, Plan, and Bypass permissions.
- Pending approvals appear inline in the conversation and in the Approvals
  view; a decision in either place updates the other. Destructive approvals
  show the channel name and a red accent.
- Auto mode can ask the active provider for a permission decision with a short,
  fail-closed prompt; timeouts, invalid JSON, low confidence, or instruction-like
  arguments fall back to a human. Every model decision and fallback is audited.
- Agents can list and delete channels, with `delete_channel` behind the approval
  gate.
- The task detail includes the plan, worktree, assignments, events, runs, and
  tool calls; the Background toggle opens the running-work panel.

## Why it matters

0.1.6 made the workspace manageable and the Main Assistant useful. 0.1.7 makes
the work itself inspectable and bounded: the context a model sees is visible and
can be compacted; permission decisions have rules, memory, a plan hand-off, and
an auditable source; and risky implementation work can run in an isolated git
checkout while the sidebar shows what is still running.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.6.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases migrate automatically through migrations `0005`–`0012`
when the app opens them: LLM call usage, task titles and archive state,
conversation sessions and context, permission rules, task plans, the workspace
Bypass policy, run groups, and task worktrees. Back up the database before
opening it with a new build if you may need to return to 0.1.6.

`.cowpkg` packages from 0.1.6 and earlier still import. New packages include
conversation data and `permission_rules.jsonl`; imported rules start disabled
and are marked `imported` until you enable them. Task worktrees and the
device-local repository registry are never written to a package.

Agents created from older templates keep their name, role, and tools. Use
Settings → Team to add the new workspace tools or switch to the Main Assistant
template.

## Known limitations

- The optional Permission model override in Settings → Model is not implemented;
  Auto mode uses the active provider and model.
- Approval risk and reason are carried by the live event, not persisted with the
  approval row. A pending approval loaded after a restart shows its tool call but
  not its risk metadata, and session approval is hidden until the risk is known.
- Worktree branches are not merged back and no pull request can be opened from
  the app; inspect the diff and merge with normal git tooling.
- Group conversations, a router, agent long-term memory, shared project notes,
  and Phase 2 self-hosted mode remain future work.
