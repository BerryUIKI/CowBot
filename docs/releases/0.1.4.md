# CowBot 0.1.4 — Agent replies in channels

CowBot 0.1.4 closes the last gap between the product description and the
desktop app: mentioning an agent in a channel now produces an answer in that
channel. Until now a channel message was persisted and broadcast but nothing
consumed it, so messages went unanswered with no indication of why.

## Highlights

- **Mention an agent to get an answer.** Post `@Planner which module owns the
  parser?` in a channel and the mentioned agent replies there. `@team` (also
  `@all`, `@everyone`, `@here`) addresses every agent in the workspace, matching
  is case-insensitive, and the channel header lists who can be mentioned. See
  [ADR-0022](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0022-channel-mention-turns.md).
- **Answers are ordinary tasks.** A mention becomes a task for that agent and
  runs through the existing assignment scheduler, so it appears in **Tasks**
  with its assignment events, run, and tool calls, and it can be cancelled like
  any other task. The answer is also posted back to the channel as a message
  from that agent, with the agent's display name in the timeline.
- **Approvals still apply.** Each channel has an approval dropdown in its
  header. A risky tool call raised while an agent answers is classified and
  gated by the same policy as a task run and appears in **Approvals**.
- **Failures are never silent.** An unknown mention posts a system notice
  listing the agents that exist, a workspace without agents points at
  **Settings → Team**, a failing turn posts the model error, and an empty answer
  posts a notice instead of a blank message. A message with no mention posts
  nothing beyond itself.
- **Background turns do not compete.** A channel turn runs in the background so
  the composer stays responsive, and two turns can run at once. A scoped
  scheduler makes each turn claim only the assignments it enqueued, so a
  background turn no longer races a task run or another turn for the same
  queued work. See
  [ADR-0023](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0023-channel-turn-scheduler-scope.md).
- **CLI parity.** `cowbot message post --channel <id> --content "@Planner what
  next?" --wait` drives the same path, so turns can be scripted and tested
  against a real endpoint.
- **Documentation.** New ADRs 0022–0023, a corrected `docs/ARCHITECTURE.md`
  §3.2 that no longer claims `Mention` and `TaskCard` entities exist, and
  mention usage, per-channel approval, and new troubleshooting entries in the
  user guide.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.3.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases, `config.json` files, and `.cowpkg` packages from
0.1.3 continue to work; there are no schema changes and no migration step.

Channel answers consume the same provider configuration as task runs. With no
active provider the desktop falls back to the offline mock model, so an answer
reads as an echo; a provider that is configured but cannot answer posts a system
notice with the model error instead of staying silent.

## Known limitations

- Local/offline single-user mode only: no server, remote sessions, or
  multi-user workspaces.
- Channel answers are one turn per mentioned agent. A reply uses the channel's
  recent history rather than a thread, mentions are derived from the message
  text and are not persisted as entities, per-channel responder rules do not
  exist, and agents never answer an unmentioned message.
- Sequential Planner → Coder → Reviewer crews; no hierarchical orchestration,
  DAG workflows, or agent-facing delegation tool.
- No streaming responses, retries, rate limiting, or token accounting.
- The subprocess sandbox is not OS-level isolation.
- Builds are unsigned; updater signatures are separate from code signing.
- Workspace deletion and renaming are not available in the desktop UI.
