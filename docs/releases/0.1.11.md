# CowBot 0.1.11 — Database lifecycle safeguards and setup polish

CowBot 0.1.11 makes the workspace database safe to open across app versions. A
startup screen explains a one-way schema upgrade and lets you upgrade directly,
back up first, or quit; a database written by a newer build offers a compatible
backup instead of an unexplained exit. The release also finishes the first-run
guide: the title bar stays draggable, a language picker and a database folder
picker are always available, and the model selector matches the rest of the
interface.

## Highlights

- **The database has its own version.** The workspace database carries a schema
  version separate from the app version, shown on the startup screen and in
  Settings → About as **Database schema**. CowBot asks only when there are
  pending migrations; a version bump with no schema change never prompts.
- **Upgrades are a choice, not a surprise.** When migrations are pending, the
  window opens on a startup screen that names the current and target versions
  and states that the upgrade is one-way. Choose **Upgrade** to migrate
  directly, **Back up and upgrade** to copy the database and its `-wal`/`-shm`
  sidecars to `cowbot.db.backup-<from>-<timestamp>` first, or **Quit CowBot** to
  leave it untouched. See
  [ADR-0051](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0051-database-lifecycle-safeguards.md).
- **A newer database is refused with a way forward.** If the file was written
  by a newer CowBot, the same screen lists backups this build can open and
  offers **Restore backup**, **Start with an empty workspace**, or **Quit**.
  Nothing is deleted: the replaced file is kept as
  `cowbot.db.replaced-<timestamp>`.
- **Development builds no longer share the installed app's data.** A debug
  build keeps its workspace and `config.json` under `app_data_dir()/dev`, and
  `COWBOT_DATA_DIR` points any build somewhere else. Running `pnpm run tauri
  dev` can no longer migrate the database an installed release is using.
- **One CowBot at a time.** A second launch exits and focuses the open window,
  so two processes cannot open the same workspace database.
- **Setup polish.** The first-run guide keeps the title bar draggable, shows a
  persistent language picker, and offers a **Database folder** picker that moves
  workspace databases to another drive and restarts into the new folder. The
  default-model, protocol, and fetched-model selectors are themed dropdowns
  instead of native popups.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.10.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

No database migration ships in this release: schema version 20 is unchanged, so
a database opened by 0.1.11 can still be opened by 0.1.10. The startup screen
appears only when a future release adds migrations.

`.cowpkg` packages from 0.1.10 and earlier still import. Prompt snapshots, LLM
usage, group turn rows, and model provider configuration remain device-local and
are never written to a package.

## Known limitations

- The desktop's settings do not yet offer choosing a server. A client that
  speaks the HTTP API or uses `RemoteClient` can reach one, and the local
  runtime remains the default way to use CowBot.
- Agent turns still execute in the desktop process with its model provider. The
  server stores and serves workspace state; a member without that provider
  configured cannot make an agent answer.
- `RemoteClient` reports server mode plainly for worktrees, in-process crew
  execution, live-turn cancellation, and process-local session decisions.
  Streaming a live turn over a remote transport is not built.
- The server is a small-team deployment for a network you control, not a public
  service. Multi-user concurrency defence for two people editing the same agent
  or rule is not implemented.
- Interface localisation covers the desktop chrome. Service diagnostics, agent
  profiles, template content, stored audit reasons, and the CLI remain in
  English; right-to-left layouts are not implemented. The planned languages
  follow Claude's picker plus Chinese.
- Worktree branches still cannot be merged back or turned into a pull request
  from the app. Prompt snapshots remain per-call evidence: audit events and tool
  calls are not yet linked to the snapshot that produced them.
- The CLI still applies pending migrations without asking; it is an operator
  tool. It refuses a database from a newer build with a message naming both
  schema versions.
