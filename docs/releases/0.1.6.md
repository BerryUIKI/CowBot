# CowBot 0.1.6 — Phase 1 polish: channel management, rich output, and the Main Assistant

CowBot 0.1.6 turns the conversation-first shell into a workspace you can manage,
and introduces the main assistant at the center of a one-person company. You can
now rename, pin, delete, and clear conversations; agent answers render Markdown
and interactive HTML; and the Main Assistant can create channels, start teams,
and queue work for specialist agents.

## Highlights

- **Manage channels and conversations.** Right-click a sidebar row, press the
  context-menu key, or use its **⋯** button. Group channels can be renamed,
  pinned, or deleted; agent conversations can be pinned or have their history
  cleared. Direct conversations cannot be deleted because the agent remains a
  contact. Deleting a group channel removes its messages, while tasks keep their
  history and lose the channel link. See
  [ADR-0026](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0026-channel-and-conversation-management.md).
- **Unique channel names.** Names are unique per workspace, case-insensitively,
  on create and rename. Existing workspaces that already contain duplicates can
  still rename or delete them; nothing is rewritten automatically.
- **Markdown and HTML output.** Agent and user messages render Markdown with
  tables, lists, code, and links; links open in your system browser. Inline HTML
  is sanitized. A fenced `html` block opens as an **HTML preview** card with
  **Preview**, **Code**, and **Expand**: the preview runs inline CSS and
  JavaScript in a sandbox that blocks network access, external images, form
  submission, storage, and access to the app. See
  [ADR-0027](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0027-rich-agent-output.md).
- **A more readable timeline.** Messages are grouped by day, sidebar previews are
  plain text, and an agent's own direct-conversation preview no longer repeats
  its name.
- **Meet `main`, the Main Assistant.** The built-in **Main Assistant** template
  ships agent `main` with a primary-assistant role for a one-person company. It
  can list agents and templates, create channels, queue tasks for specialist
  agents, and add a team from a template. Each action goes through the normal
  approval policy, and the approval card shows the tool name, arguments, risk,
  and reason. See
  [ADR-0028](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0028-main-assistant-and-workspace-actions.md).
- **Edit any agent.** Settings → Team and an agent conversation's context menu
  open an editor for name, role, and tool selection. Names are unique, and the
  agent's direct conversation follows a rename. Existing assistants can be
  renamed to `main` and given the workspace tools without starting over.
- **Explicit boundaries.** `create_task` queues a pending task; it does not run
  the assigned agent automatically. Workspace tools are available in the
  desktop app; the CLI's channel turns do not expose them yet.

## Why it matters

The conversation-first shell from 0.1.5 answered a message but could not manage
the workspace around it. 0.1.6 closes that loop: the primary assistant can shape
the workspace, specialists receive queued work, and the human can see and approve
exactly what an agent is about to do. Rich output makes the answer itself a
usable interface, not just text.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.5.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases, `config.json` files, and `.cowpkg` packages from 0.1.5
continue to work. Migration 0004 adds the `pinned` flag automatically on first
launch; every existing channel starts unpinned.

Agents created from the old general-assistant template keep their old name, role,
and tools. Use **Edit** in Settings → Team or the conversation menu to rename one
to `main`, set its role, and enable `create_channel`, `create_task`,
`instantiate_team`, `list_agents`, and `list_templates`; adding the **Main
Assistant** template is the alternative.

The 0.1.5 migration-checksum repair still applies. If a database is repaired and
then opened by 0.1.6, an older build (0.1.4 and earlier) will refuse to open it;
restore the pre-repair backup to go back.

Workspace actions consume the same provider configuration as any other turn. With
no active provider the desktop falls back to the offline mock model, so answers
read as echoes; a provider that cannot answer posts a system notice with the
model error instead of staying silent.

## Known limitations

- Local/offline single-user mode only: no server, remote sessions, or multi-user
  workspaces.
- Workspace tools are desktop-only; the CLI's channel turns do not expose them,
  and `create_task` leaves the task pending for you to run.
- HTML previews cannot reach the network, external images, or the app, and a
  button inside one cannot send a message back to the agent yet.
- Agents cannot be deleted from the UI; edit their name, role, or tools instead.
- Each agent has one direct conversation, and it cannot be renamed independently
  of the agent or deleted from the channel list. There are no unread counts,
  attachments, streaming answers, or multi-user direct messages.
- Group channel answers are one turn per mentioned agent. A reply uses the
  channel's recent history rather than a thread, and agents never answer an
  unmentioned message in a group channel.
- Sequential Planner → Coder → Reviewer crews; no automatic delegation run,
  hierarchical orchestration, or agent-facing delegation tool.
- No streaming responses, retries, rate limiting, or token accounting.
- The subprocess sandbox is not OS-level isolation.
- Builds are unsigned; updater signatures are separate from code signing.
- Workspace deletion and renaming are not available in the desktop UI.
