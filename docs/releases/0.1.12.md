# CowBot 0.1.12 — Startup fixes

CowBot 0.1.12 fixes the two problems reported after updating to 0.1.11: a
development build can no longer stand in for the installed app, and a workspace
that fails to load offers a retry instead of an empty window. No database
migration ships, so nothing about a workspace changes.

## Fixes

- **A development build no longer takes the instance lock.** One CowBot still
  runs at a time: a second launch focuses the open window. The lock is named
  after the bundle identifier, which a `tauri dev` build shares with the
  installed app although it keeps its own data under `app_data_dir()/dev`.
  While such a build was running, launching the installed app made the installed
  process exit and focused the development window — a window with no model
  providers and an empty workspace, which looks like an update that lost
  everything. Only a release build registers the plugin now, so a development
  build and the installed app can run side by side without sharing data. See
  [ADR-0051](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0051-database-lifecycle-safeguards.md).
- **A failed startup load can be retried.** The shell loads the session,
  channels, agents, templates, onboarding state, projects, and conversation
  summaries in one batch. If any call fails, the window now names the reason and
  offers **Retry**, which reruns the batch and reloads the model configuration,
  instead of leaving an empty shell behind a dismissible banner.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.11.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

No database migration ships in this release: schema version 20 is unchanged, so
a database opened by 0.1.12 can still be opened by 0.1.11. Workspace packages,
prompt snapshots, usage rows, and model provider configuration are untouched.

An installed 0.1.11 keeps the shared instance lock until 0.1.12 is installed, so
starting a development build before the installed app can still focus the
development window once.

## Known limitations

Unchanged from 0.1.11; see [the limitations page](../LIMITATIONS.md).
