# CowBot 0.1.16 — The desktop can open a workspace on a CowBot server

CowBot 0.1.16 finishes Phase 2 milestone 2.3. The self-hosted server has existed
since 0.1.10 with a complete client and API behind it, but the desktop never
used it: there was no way to point the app at a server. Now there is. Settings →
Server signs in, picks a workspace, and CowBot opens that workspace instead of
the local database — resuming the session on every later launch, reconnecting
when the network drops, and hiding the actions that only work on the machine
running the app.

No database migration ships: schema version 20 is unchanged, so a workspace
opened by 0.1.15 opens unchanged.

## Changes

- **Connect to a server from Settings.** **Settings → Server** takes the
  deployment's HTTPS address, an email, and a password. CowBot signs in and
  lists the workspaces the account can enter; choosing one saves the connection
  and restarts into it. Nothing is written until you press **Connect**, so a
  refused password leaves the open workspace exactly as it was. The section also
  switches between the account's workspaces without asking for the password
  again, tests the saved session, returns to the local workspace while keeping
  the session, and disconnects and forgets it. The session token is stored on
  this device in `config.json`, beside model API keys, and is never returned to
  the interface.
- **A restart resumes the session.** Launching CowBot in server mode rebuilds
  the client from the stored token, so the password is asked for once.
- **The live stream reconnects.** A dropped connection retries with backoff
  instead of leaving a screen that looks live while it is silently stale. When
  it recovers, the window reloads channels, agents, tasks, approvals, the open
  timeline, and the background overview, because events published while the
  socket was down were never delivered. A session the server has revoked stops
  the retries and asks you to sign in again.
- **An unreachable server is reported, not guessed at.** If the saved server
  cannot be reached at startup, CowBot names the address and the error and
  offers **Try again** or **Open the local workspace instead**. It no longer
  raises a database-upgrade question about a local file it is not going to open.
- **Local-only actions are hidden in server mode.** Running a task, project
  worktrees and repositories, local workspace creation and switching, workspace
  package export and import, context compaction and auto-compaction, the profile
  editor, and session approvals disappear rather than failing on click. Agent
  turns still run in the desktop's process with your own model provider, so the
  member who opened the workspace is the one who can make an agent answer.
- **Thirteen languages.** Every new string ships in all thirteen interface
  catalogues.

## What does not change

CowBot remains local-first. The default mode is still one SQLite file on your
machine, and nobody has to run a server to use the app. Server mode is an
addition, chosen per device, and switching back is one button.

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.15.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

No database migration ships: schema version 20 is unchanged, so a database
opened by 0.1.16 can still be opened by 0.1.15. An existing `config.json` has no
server block and keeps opening the local workspace; model providers, workspace
packages, prompt snapshots, and usage rows are untouched.

## Known limitations

- Agent turns, crews, context compaction, worktrees, and live-turn cancellation
  still need the local runtime; see [the limitations page](../LIMITATIONS.md).
- The server has no profile-edit route yet, so the account name and email are
  read-only in server mode.
- Switching backends restarts CowBot.

See [ADR-0053](../ADR/0053-desktop-server-mode.md) for the decision, and
[SERVER.md](../SERVER.md) for deploying the server.
