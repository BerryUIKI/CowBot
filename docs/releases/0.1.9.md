# CowBot 0.1.9 — Slash commands, side questions, and auditable prompts

CowBot 0.1.9 makes the composer a keyboard surface, asks questions to the side
of a conversation, and lets you read exactly what was sent to the model. Every
action you used to reach through a right-click menu, the context popover, or
Settings is now one `/command` away, and `/btw` runs a turn that never becomes
part of the conversation. Recorded prompt snapshots seal the request behind
every model call, redacted, so an audit review no longer has to reconstruct it
after the fact. Context meters and compaction count tokens with the
conversation model's real tokenizer where one exists, compaction itself is
race-free, and the desktop's TypeScript types are now generated from Rust.

## Highlights

- **Slash commands.** Typing `/` at the start of the composer opens a command
  menu driven by a catalogue and parser in `cowbot-core`, so the CLI and future
  remote clients share the same names, aliases, quoting, and arity rules.
  Sixteen commands cover help, chat management, context compaction and
  clearing, notes and memory, task creation, model and approval switching,
  cancellation, and Settings navigation. Commands are desktop actions and
  never become messages or context entries; context commands require a
  user-created conversation, destructive commands keep their confirmations, and
  an unknown first token shows a hint that Escape overrides, so path-like
  input such as `/usr/bin/env python` still sends. See
  [ADR-0038](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0038-slash-commands.md).
- **Side questions with `/btw`.** `/btw <question>` asks an agent something
  without adding it to the conversation: the turn runs with the same tools and
  approval gate as a normal one, but posts no message, appends no context
  entry, and records no routing turn. The answer appears in a dismissible
  panel above the composer and is gone when dismissed or on chat switch; the
  agent cannot remember it afterwards. Its cost is still recorded, as a
  `side_question` call kind, so Settings → Audit shows it. One responder is
  chosen deterministically — an explicit `@mention`, the conversation's default
  responder, or its agent — and a question naming several agents is refused.
  See
  [ADR-0039](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0039-side-questions.md).
- **Recorded prompt snapshots.** Every LLM call can store a sealed, redacted
  snapshot of the request that produced it: ordered messages with tool-call
  arguments, tool schemas, prompt slots, the memory block with its selected
  entry ids, the model, the call kind, a token count, and a content hash. A
  per-workspace capture switch and retention window govern it, a task's
  **Recorded prompts** action opens a read-only viewer, and Settings → Audit
  adds the newest snapshots, a purge action, and the retention controls.
  Snapshots never leave the device and never cross a workspace package. See
  [ADR-0037](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0037-prompt-snapshots-for-audit.md).
- **The context inspector.** The right inspector's Context tab renders the
  read-only next-request plan for a conversation participant (with the composer
  draft) or a task run's first request: the prompt slots, ordered messages,
  tool schemas, the memory recall trace with skip reasons, and the budget with
  an over-budget state. It answers "what would be sent", as the audit snapshot
  answers "what was sent". See
  [ADR-0036](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0036-context-preview-and-recall-trace.md).
- **Model-aware token counting.** Context meters, compaction thresholds and
  splits, and the router history budget count with the conversation model's
  tokenizer when one exists — OpenAI-compatible `o200k_base` and `cl100k_base`
  vocabularies are compiled in — and label the character-estimate fallback
  otherwise, with the tokenizer name shown. The memory estimate is labelled
  separately. See
  [ADR-0035](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0035-model-aware-token-counting.md).
- **Race-safe compaction.** Compaction now runs per branch under a
  process-shared lock, inserts the summary at the cutoff, and renumbers the
  kept tail in one transaction, so a concurrent clear or reply cannot observe
  a half-compacted branch. The context popover surfaces compaction progress and
  refuses to start a second run on the same branch. Imported packages normalize
  legacy context sequence numbers. See
  [ADR-0034](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0034-compaction-concurrency.md).
- **One Chats list.** The sidebar merges agent direct chats and group channels
  into a single Chats list (pinned first, then recent activity), the
  Conversations section collapses, and task detail, approvals, and running
  progress moved into the right inspector so task work stays beside chat
  instead of replacing it. Tasks are tagged with their source, so conversation
  turns are hidden behind **Show conversation turns** in the task list.
- **Generated desktop types.** The desktop's TypeScript types are generated
  from the Rust definitions with `ts-rs` behind an opt-in `bindings` feature.
  The generated directory is committed and CI regenerates and checks it before
  the frontend build, so a Rust rename that the desktop has not adopted fails
  the pull request instead of the user. Generation immediately caught three
  real mismatches the hand-written mirror had been hiding. See
  [ADR-0040](https://github.com/BerryUIKI/CowBot/blob/main/docs/ADR/0040-generated-desktop-types.md).

## Upgrade

- **Windows (NSIS setup):** updates in-app from 0.1.8.
- **Windows (MSI):** install the new NSIS setup or MSI manually.
- **macOS (from the DMG):** updates in-app. Builds remain unsigned and
  un-notarized, so macOS may ask you to allow CowBot again after an update.
- **Linux (AppImage):** updates in-app.
- **Linux (deb):** download and install the new package.

Existing local databases migrate automatically through migrations `0015`–`0017`
when the app opens them: task sources, the executing agent profile on runs, and
the prompt snapshot tables. Back up the database before opening it with a new
build if you may need to return to 0.1.8.

`.cowpkg` packages from 0.1.8 and earlier still import. Prompt snapshots and
LLM call usage remain device-local and are never written to a package.

## Known limitations

- Slash commands are executed by the desktop only. The `cowbot` CLI uses the
  same catalogue and parser but does not yet run commands, command history is
  not kept, and `/model` cannot switch to a model on an inactive provider.
- A side question cannot use conversation history, by design; put anything you
  want kept into the conversation itself.
- Group turns cannot be cancelled mid-turn or retried per participant, and
  consolidated group-plan approval is deferred; streaming responses (issue
  #180) remain future work.
- Prompt snapshots are per-call evidence only: audit events and tool calls are
  not yet linked back to the snapshot that produced them.
- Model-aware token counting covers OpenAI-compatible families; Claude,
  DeepSeek, and local runtimes still use the labelled character estimate.
- Worktree branches still cannot be merged back or turned into a pull request
  from the app; inspect the diff and use normal git tooling.
