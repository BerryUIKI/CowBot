# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

CowBot is an open-source, high-performance multi-agent collaboration platform with code execution and automation capabilities, built in Rust. It utilizes an event-driven message bus for decoupled multi-agent communication and modular tool sandboxing.

## Git Workflow (GitFlow)

- **Strict rule**: NEVER push directly to `dev` or `main`. Both branches have GitHub branch protection enabled with pull request requirements and force-push/deletion blocked.
- `main` — release-ready history only; protected.
- `dev` — integration branch for completed features; protected. All feature pull requests must target `dev`.
- `feature/<name>` — branched from `dev`, pushed to origin, and merged into `dev` via Pull Request (`gh pr create --base dev`).
- `release/<version>` — branched from `dev` when preparing a release, merged into both `main` and `dev` via Pull Request.
- `hotfix/<name>` — branched from `main` for urgent fixes, merged into both `main` and `dev` via Pull Request.
- Commit messages are small, atomic, and English; always use PRs to merge into `dev`.

## Language

All repository artifacts — code, comments, documentation, commit messages, and branch names — must be written in English. Conversation with the user may be in Chinese; do not add mixed-language sections to docs.

## Workspace Architecture

The project is structured as a Cargo workspace under `crates/`:

- **`crates/cowbot-core`**: Core domain types and shared errors (`CowError`). Defines `AgentProfile`, `Task`, `Channel`/`ChannelMessage` (a channel with `agent_id` is that agent's direct conversation, ADR-0024; `pinned` records user pinning, ADR-0026; `kind` distinguishes group channels, direct conversations, and user-created conversations, ADR-0030), conversation sessions with settings, ordered participants, append-only `ContextEntry` branches with optional peer authorship, context events, projection, and compaction helpers (ADR-0030, ADR-0032), routing sources and group turn records, notes and memory entries with four scopes, statuses, sources, budgets, deterministic ranking and selection, notes rendering, and deterministic credential redaction (ADR-0033), task run groups, task sources that separate user work items from channel and conversation turns, and git worktree lifecycle types (ADR-0031), `@mention` parsing and resolution (ADR-0022), the `Tool` trait, the `Event`/`EventPayload` bus message model (including assignment, worktree, and conversation-routing events, ADR-0031, ADR-0032), and normalized LLM token-usage types plus a character-based estimator (ADR-0029).
- **`crates/cowbot-bus`**: Tokio broadcast-backed `EventBus` with subscriber handles and a bounded in-memory event history.
- **`crates/cowbot-tools`**: `ToolRegistry` plus the built-in tools (`CodeExecutionTool`, `ReadFileTool`, `WriteFileTool`), the pluggable `SandboxBackend` trait implemented by `SubprocessSandbox`, and the deterministic `StaticRiskClassifier`.
- **`crates/cowbot-llm`**: `LlmProvider` abstraction with an OpenAI Chat Completions client (works with OpenAI, DeepSeek, Ollama, etc.), an Anthropic Messages client (Claude and Claude Code-compatible relays), an OpenAI Responses client (Codex-style endpoints), and a `MockLlmProvider` for offline tests and dry runs. Responses carry normalized token usage, including DeepSeek cache hit/miss fields, and preserve the provider's raw usage object. `LlmProvider::list_models` queries each protocol's model catalogue for the desktop's Fetch models action (ADR-0021).
- **`crates/cowbot-agent`**: Agent runtime loop (LLM call → tool calls → observations), an optional `ToolGate` consulted before each tool execution, an optional `LlmUsageRecorder` invoked after every completion, an optional `ConversationRecorder` that mirrors assistant/tool messages into a conversation branch, `execute_messages` for caller-assembled requests (ADR-0030), sequential `Crew` orchestration, and preset roles in `StandardRoles` (Planner, Coder, Reviewer).
- **`crates/cowbot-store`**: SQLite persistence built on `sqlx`: embedded migrations, connection management, and repository methods for identity, collaboration, agents/templates, tasks (including run groups and sources)/assignments/runs/tool calls/LLM calls/approvals, task worktree records (ADR-0031), conversation settings with the default responder, participants with roster positions, context entries with peer authorship, context events, and device-local group turn records (ADR-0030, ADR-0032), notes, memory entries with an FTS5 trigram index maintained by triggers (insert/update/delete, including cascades), filtered entry listing, pinned and scope-aware recall search with a LIKE fallback, recall statistics, and workspace memory settings (ADR-0033).
- **`crates/cowbot-client`**: Transport-neutral `Client` trait and the local-mode `LocalClient`, which opens SQLite, bootstraps the local workspace, runs startup reconciliation, and exposes session, channel/message and channel-management operations (rename, pin, delete, clear history), conversation creation from a `NewConversation` value (single or ordered group participants), conversation summaries with participant profiles, participants, routing turns, settings, context projection, per-participant clearing and compaction, and local compaction (ADR-0030, ADR-0032), memory notes, entry CRUD with approval and archive, settings, and a recall preview, channel turns (`reply_to_mentions`), agent conversation provisioning (`ensure_agent_channels`), agent profile updates (`update_agent`), run-group task listing, local-only worktree request/prepare/get/list/diff/discard/reconcile operations (ADR-0031), template, agent, task/assignment/approval, history (runs, tool calls, assignment events, audit), and event-stream operations without leaking store or service types.
- **`crates/cowbot-package`**: `.cowpkg` workspace packages (ADR-0004): ZIP container with a manifest, per-file SHA-256 checksums, export of a workspace, and verified import that always creates a new workspace. Packages carry notes, memory entries, and memory settings; export redacts credentials, and import re-keys and normalizes unknown memory states (ADR-0033).
- **`crates/cowbot-service`**: Application services for the local runtime: idempotent local owner/workspace bootstrap, channel/message operations that persist first and then publish events, channel name validation and management with rename, pin, delete, and clear history (ADR-0026), idempotent agent direct-conversation provisioning (ADR-0024), agent profile updates that keep conversations in sync (ADR-0028), channel turns that turn mentions or direct messages into assignment-backed answers with CowBot/OPC context (ADR-0022, ADR-0028), single-agent conversation sessions with independent append-only context branches, projection, compaction, clearing, and channel-attributed usage (ADR-0030), group conversation creation, participant-scoped mention and default-responder routing, an opt-in model router with documented fallbacks, per-participant branches with peer mirroring, observed reply posting, turn-row persistence, and post-routing capacity skips (ADR-0032), memory and notes with scoped recall, prompt injection for conversation and task turns, the scoped `remember` tool, opt-in extraction with pending review, and package-safe redaction (ADR-0033), the assignment runtime (tree lifecycle, event log, budgets, stall guard, restart reconciliation), the assignment scheduler with wake/re-entry, cross-root concurrency, prepared conversation requests, and run-bound usage recording (ADR-0019, ADR-0029, ADR-0030), the worktree service that requests, prepares, inspects, discards, and reconciles per-task git worktrees and publishes `WorktreeUpdated` (ADR-0031), the approval service (risk policy, workspace allow / ask / deny rules, session decisions, the Bypass Critical tri-state, pending approvals, source-attributed audit), a scheduler-backed crew runner, and template management with built-in templates, validation, CRUD, and `.cowtemplate` import/export.
- **`crates/cowbot-cli`**: The `cowbot` binary. `init` opens the local database through `cowbot-client` and prints the session; `run` executes the Planner/Coder/Reviewer crew through `LocalClient::run_crew_with_options` with persisted history, `--db`, `--dry-run`, `--channel`, `--concurrency`, and an interactive `--approval` policy; `channel` and `message` list/create channels and list/post messages (`message post --wait` lets mentioned agents answer; on a group conversation it prints the route source and per-agent reply, failure, and skip counts); `memory` lists, adds, and archives memory entries; `tools` inspects the registry and smoke-tests the sandbox. Settings resolve from `--config`/`COWBOT_CONFIG`/`cowbot.toml` with CLI and environment values taking precedence, and API keys stay in environment variables (ADR-0020).

## Website

`site/` holds the GitHub Pages landing page (plain HTML/CSS/JS, no build step): a hero with an interactive approval demo, platform download links resolved from the GitHub Releases API, feature and architecture sections, and a quick start. It is published from the `gh-pages` branch, which holds an assembled copy of `site/` plus `assets/brand/` and `docs/assets/` so relative asset paths resolve. The `gh-pages` branch is generated output; edit `site/` and republish it with `bash site/publish.sh` (add `--dry-run` to write to `tmp/gh-pages/` without pushing). Pages serves that branch's root.

## Desktop App

The desktop app lives under `desktop/` and is not part of the Cargo workspace:

- **`desktop/`**: React 19 + TypeScript + Vite frontend, built with pnpm (ADR-0015). It has a three-step first-run onboarding overlay (welcome, model, starter team) and a conversation-first shell (ADR-0024): a searchable sidebar with one Chats list that merges agent direct chats and group channels (avatars, last-message previews, up to two live background task cards per channel, pinned-first then recent activity), a collapsible Conversations section with New conversation (one agent or an ordered group of up to eight with a default responder and routing toggle) and group avatars, right-click management (pin, rename, delete, clear history/context, ADR-0026, ADR-0030), a sidebar header that returns to Chat, opens the task list, and starts a new channel, a Settings gear in the local user row, a bubble chat timeline with a typing indicator and a floating composer, and chat, task-creation, and settings views (task creation with an optional project worktree, task detail with run tasks, assignments/events/runs/tool calls and a Worktree card with branch copy, diff, open-folder, and discard actions, cancellation, desktop-initiated execution; pending approvals with approve/reject; workspace identity and workspace switching/export/import, vendor-first model providers with protocol selection, model discovery, multiple models per provider, and optional context-window metadata, agents, templates, registered local git projects under Settings → Projects, workspace permission rules, session decisions, and the Bypass Critical setting under Settings → Approvals, a source-filtered audit view under Settings → Audit, and an About section with version and update controls). Messages and task deliverables render Markdown and sanitized inline HTML, and fenced `html` blocks render as sandboxed HTML artifacts (ADR-0027). Settings → Team and the agent context menu edit an agent's name, role, and tools; the built-in Main Assistant can create channels, instantiate teams, and queue tasks through desktop workspace tools, including into a registered project's worktree, with approval cards showing the tool call (ADR-0028, ADR-0031). Settings → Memory edits the workspace note, recall and extraction flags, token budgets, a filterable entry list with pending review, and entry add/edit/pin/archive/delete actions; a conversation's context popover edits its note and exposes the next turn's memory estimate; user messages offer "Remember this message" (ADR-0033). Conversation headers show a context ring and popover with percent used/left, a colored stacked bar and labeled legend (messages blue, memory gray, system prompt yellow, tools orange, auto-compact buffer dark gray, free space neutral), the tokens remaining until auto-compaction, a detailed breakdown with per-category tokens and cache hit rate, auto-compaction controls, and compact/clear/new actions; a full context blocks the composer (ADR-0030, ADR-0033). Group conversations show participant chips with the default responder marked, one context tab per participant with per-branch compact/clear, a routing toggle and default-responder select, an Answered-by line with reload-safe routing details and failure/skip chips, and a keyboard-accessible mention autocomplete; a full branch is skipped without blocking the send (ADR-0032). The chat header opens a right-side inspector with Task, Approvals, and Background tabs, each with a count where relevant; the Task tab lists tasks (conversation turns hidden behind **Show conversation turns**) and opens a task's detail with a back control and collapsible prompt, so task detail, approvals, and running progress stay beside Chat instead of replacing it. Below about 1080px the sidebar hides while the inspector is open, and below 760px the inspector overlays (ADR-0031). It refreshes from Tauri events.
- **`desktop/src-tauri/`**: Standalone Tauri v2 Cargo project. Opens `LocalClient` on the active workspace database (`app_data_dir()/cowbot.db` by default, or a registered database under `app_data_dir()/workspaces/`), stores model providers (with their known model lists and optional per-model context-window metadata), the onboarding flag, the update-check preference, the workspace registry, and the device-local project registry in `app_data_dir()/config.json`, exposes Tauri commands that wrap the `Client` trait (session, channels/messages and channel management, agent conversation provisioning, agent profile updates and available tools, agents/templates, tasks and run-group tasks, assignments, runs, tool calls, approvals) plus conversation commands (`create_conversation` with one agent or an ordered participant list, `list_conversation_summaries`, `list_conversation_participants`, `list_conversation_turns`, `get_conversation_context` with per-participant meters and routing settings, `update_conversation_settings`, `compact_conversation` and `clear_conversation_context` with an optional participant), memory commands (`get_memory_notes`, `save_memory_note`, `delete_memory_note`, `get_memory_settings`, `update_memory_settings`, `list_memory_entries`, `add_memory_entry`, `update_memory_entry`, `approve_memory_entry`, `dismiss_memory_entry`, `archive_memory_entry`, `delete_memory_entry`, `preview_memory_recall`), project commands (`list_projects`, `add_project`, `remove_project`, `list_project_branches`), worktree commands (`get_task_worktree`, `task_worktree_diff`, `discard_task_worktree`) and the background overview (`list_task_overview`), model provider commands (`get_model_settings`, `save_model_provider`, `delete_model_provider`, `activate_model_provider`, `test_model_provider`, `fetch_provider_models`), onboarding commands (`get_onboarding_state`, `complete_onboarding`), app commands (`get_app_info`, `set_auto_check_updates`, `restart_app`), and workspace commands (`list_workspaces`, `switch_workspace`, `export_workspace`, `import_workspace`), and forwards client events on the `cowbot-event` channel. Group reply events on `cowbot-channel-reply` carry the selected, replied, failed, and skipped agents, the route source, and the turn id, and group sends pass per-participant usable windows and tool-schema tokens for the post-routing capacity check (ADR-0032). The Tauri updater and opener plugins back in-app updates, release-note links, and revealing worktree folders; API keys never cross back to the frontend.
- **Architecture**: see `docs/ADR/0009-desktop-ipc-and-state.md`, `docs/ADR/0012-local-model-configuration.md`, `docs/ADR/0013-first-run-onboarding.md`, `docs/ADR/0014-desktop-release-builds.md`, `docs/ADR/0015-pnpm-for-desktop-dependencies.md`, `docs/ADR/0016-model-provider-protocols.md`, `docs/ADR/0017-desktop-workspace-transfer.md`, `docs/ADR/0018-desktop-auto-updates.md`, `docs/ADR/0021-vendor-first-model-providers.md`, `docs/ADR/0024-agent-direct-conversations.md`, `docs/ADR/0026-channel-and-conversation-management.md`, `docs/ADR/0027-rich-agent-output.md`, `docs/ADR/0028-main-assistant-and-workspace-actions.md`, `docs/ADR/0030-conversation-sessions-and-context.md`, `docs/ADR/0031-task-worktrees-and-background-cards.md`, `docs/ADR/0032-group-conversations-and-routing.md`, and `docs/ADR/0033-agent-memory-and-shared-notes.md`. The frontend never touches SQLite or `cowbot-service`.
- **Release builds**: `.github/workflows/release.yml` builds unsigned NSIS/MSI, universal DMG, deb, and AppImage bundles on `v*` tags and manual dispatches; tag runs create draft GitHub Releases. Updater artifacts are signed with the `TAURI_SIGNING_PRIVATE_KEY` secret, and a final job publishes `latest.json` for the in-app updater (ADR-0018). Tags must match `desktop/src-tauri/tauri.conf.json`.
- **Gates**: root `cargo fmt/clippy/test --workspace` intentionally excludes `src-tauri`; run `pnpm run build`, `cargo fmt --manifest-path desktop/src-tauri/Cargo.toml -- --check`, `cargo test --manifest-path desktop/src-tauri/Cargo.toml`, and `cargo clippy --manifest-path desktop/src-tauri/Cargo.toml --all-targets -- -D warnings` when changing the shell.

## Common Development Commands

### Building
```bash
cargo build --workspace
cargo build --release --workspace
```

### Running the CLI
```bash
cargo run -p cowbot-cli -- --help
cargo run -p cowbot-cli -- tools
cargo run -p cowbot-cli -- init --db cowbot.db
cargo run -p cowbot-cli -- run --task "Analyze and write code" --dry-run
```

### Running the Desktop App
```bash
cd desktop
pnpm install
pnpm run tauri dev        # dev window + Vite server
pnpm run build            # type-check and bundle the frontend
pnpm run tauri build -- --no-sign   # local bundles without updater signatures
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

`pnpm run tauri build` without `--no-sign` needs the updater signing key; CI supplies it from repository secrets. See `desktop/README.md`.

### Testing
```bash
# Run all workspace tests
cargo test --workspace

# Run tests for a specific crate
cargo test -p cowbot-core
cargo test -p cowbot-bus
cargo test -p cowbot-tools

# Run a single specific test
cargo test -p cowbot-bus -- test_bus_publish_and_receive --exact
```

### Linting & Formatting
```bash
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --check
cargo fmt
```
